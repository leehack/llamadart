# Multimodal embedding fixture v1

Private validation inputs for https://github.com/leehack/llamadart/issues/1194.
These synthetic signals test transport, ordered composition and numerical parity;
they do not measure retrieval quality or speech understanding.

- `v1/checker.png`: 224 × 224 RGB, alternating black/white 16-pixel squares,
  lossless PNG with stored DEFLATE blocks. 150,830 bytes; SHA256
  `48907b2f7a4c600cdbc4de829a7badc4801f48b2e53816276bbc81f31367e030`.
- `v1/tone.wav`: one second of 250 Hz square tone at ±4096, mono 16 kHz,
  signed 16-bit PCM WAV. 32,044 bytes; SHA256
  `963aa326ea0d5067c3981f029116ce68a33518463b23035d503b4350f4b5f8b3`.
- `v1/reference.json`: five normalized 768-component native CPU vectors,
  provenance, and model/projector hashes. 109,034 bytes; SHA256
  `382b8067c257c5713931d2d40640d0ba203279eaad5b7b5ef599654c517133fe`.

Regenerate inputs with Python's standard library:

```sh
python3 packages/llamadart_validation/assets/embeddings/generate_fixtures.py /tmp/new-embedding-inputs
```

The generator uses no transcendentals or compression heuristics. The fixture
regression checks exact output hashes in a temporary directory. Reference vectors
are not generated by the code under test. `reference.cpp` uses upstream APIs and
decodes the exact PNG/WAV through mtmd, clears context memory between inputs and
L2-normalizes the full pooled output. Its five rows, in order, are:

1. `The Eiffel Tower is in Paris.`
2. Checkerboard image.
3. Square tone audio.
4. `first `, image, ` between `, audio, ` last`.
5. `first `, audio, ` between `, image, ` last`.

The profiles lock EmbeddingGemma-2 BF16 and its BF16 projector from
`ggml-org/embeddinggemma-2-GGUF@bfcd298762cc34d0357ece5ebdd31791a3a374d8`.
The published Q8_0 model/projector pair is smaller (309,855,456 + 554,821,024
bytes), but has no native CPU references in this pack. BF16 was selected to
produce verifiable references from the maintainer's existing local files without
weight downloads. Never compare a Q8_0 run to these BF16 vectors. Add a distinct
versioned reference cohort and hash before introducing that profile.

## Reproduce references

The checked-in vectors were generated on macOS 26.7.1 arm64 with the actual
consumed `llamadart-native` v0.7.0-1 library. Its SHA256 is recorded in
`reference.json`. Use upstream headers at exactly
`620d2225cc436ab0b001e3200e590e3b286ef9ab`, not the head of a sibling checkout.
Follow the [native reference setup](../../../../doc/multimodal_embeddings_native.md#upstream-only-reference)
to obtain those headers and the consumed runtime. No Dart engine or adapter is
linked into the reference program.

```sh
clang++ -std=c++17 -O2 -I"$LLAMA_CPP_SOURCE/include" \
  -I"$LLAMA_CPP_SOURCE/ggml/include" -I"$LLAMA_CPP_SOURCE/tools/mtmd" \
  packages/llamadart_validation/assets/embeddings/reference.cpp \
  -L"$NATIVE_LIBRARY_DIR" -lllamadart -Wl,-rpath,"$NATIVE_LIBRARY_DIR" \
  -o "$TMPDIR/embedding-reference"
"$TMPDIR/embedding-reference" "$MODEL" "$PROJECTOR" cpu \
  "$TMPDIR/reference-cpu.json" \
  "$PWD/packages/llamadart_validation/assets/embeddings/v1"
# Repeat with metal and a separate output to measure the backend spread.
```

The executable writes a JSON array of vectors. To create a new reference fixture,
wrap it with the existing schema's immutable artifact/runtime/host identities,
context 2048 and four threads; verify the model and projector SHA256/size first.
Keep the native stderr and command as evidence. Update the compiled reference
hash, version/directory and docs together. A missing or changed file errors every
embedding case; a profile with different artifact hashes cannot reuse this cohort.
Reference refreshes require a reviewed fixture version, not relaxed thresholds.

## Numerical contract

Both cosine ≥ 0.9999 and maximum absolute component error ≤ 0.002 are required.
Vector width is 768; nonfinite values and zero norms cannot pass. Normalized
vectors must have norm within 1e-6 of one; `normalize: false` must return a
non-unit raw vector whose normalization passes the same CPU reference gate.

Measured CPU-versus-Metal spread on this fixture/runtime (one run per backend):

| Row | Cosine | Maximum absolute error |
| --- | ---: | ---: |
| Text | 0.999996863 | 0.000337743 |
| Image | 0.999995049 | 0.000417841 |
| Audio | 0.999900635 | 0.001568219 |
| Mixed | 0.999982139 | 0.000697839 |
| Reversed mixed | 0.999975319 | 0.000777091 |

The cosine floor preserves the prior native CPU/Metal audit's 0.9999 gate;
the 0.002 component limit leaves about 27.5% margin above this observed maximum.
Audio has only 6.35e-7 cosine margin. This is a strict conformance gate, not a
statistical tolerance estimate: a different device that misses it must retain
FAIL and undergo native reference diagnosis. The previous Web audit's 0.99998
floor does not qualify this pack's Web path. Web and LiteRT-LM remain NOT_RUN
until their own locked inputs and reference adapters are implemented.
